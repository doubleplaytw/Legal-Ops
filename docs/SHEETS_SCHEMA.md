# Google Sheets Schema — Legal Ops Dashboard

> 由前端程式碼（`src/`）反推產出。工作表名稱一旦建立**絕對不得更改**，sheets.js 以名稱定址，改名會立即壞掉 API 串接。

---

## 一、Google Sheets 建立步驟

依序建立以下 8 個工作表分頁（Tab），順序建議如下：

| 建立順序 | 工作表名稱 | 主要維護者 |
|----------|-----------|-----------|
| 1 | 律師設定 | 所長手動更新 |
| 2 | 客戶主檔 | 律師 / Apps Script 自動寫入 |
| 3 | 案件 | 律師 / Apps Script 自動寫入 |
| 4 | 接觸紀錄 | 律師手動更新 |
| 5 | 追蹤事項 | 律師手動更新 |
| 6 | 期限事件 | 律師手動更新 |
| 7 | 帳務 | 管理人員每月更新 |
| 8 | 文件連結 | 律師手動更新 |

---

## 二、各工作表欄位定義

---

### 1. 律師設定

**用途：** 各律師的案件上限、計費目標、收款目標，由所長手動維護。所有達成率由前端計算，不存入 Sheets。

**API 讀取：** `律師設定!A2:L`

> ⚠️ `sheets.js` 目前 `fetchRange` 寫的是 `A2:H`，但實際解構需要 A 到 L 共 12 欄，**上線前需將範圍修正為 `律師設定!A2:L`**。

| 欄 | 欄位名稱 | 資料類型 | 說明 | 範例值 | 必填 |
|----|---------|---------|------|--------|------|
| A | 律師ID | 文字 | 單一英文字母代號，全所唯一 | `A` | 是 |
| B | 姓名 | 文字 | 律師真實姓名 | `王大明` | 是 |
| C | 案件上限 | 整數 | 同時進行案件數量上限 | `10` | 是 |
| D | 本季預計結案數 | 整數 | 所長設定的季度結案目標 | `12` | 是 |
| E | 本季累計結案數 | 整數 | 本季已實際結案件數，每結一案更新 | `7` | 是 |
| F | 上季結算結案數 | 整數 | 上季最終結案數，季末結算後填入 | `11` | 是 |
| G | 本季累計計費時數(hr) | 數字 | 本季實際累計計費時數 | `215` | 是 |
| H | 季度計費目標(hr) | 數字 | 所長設定的季度計費時數目標 | `360` | 是 |
| I | 上季計費時數(hr) | 數字 | 上季結算計費時數 | `332` | 是 |
| J | 本季收款目標(NTD) | 整數 | 所長設定的季度收款目標（元） | `180000` | 是 |
| K | 本季已收金額(NTD) | 整數 | 本季實際已收金額（元） | `129600` | 是 |
| L | 上季已收金額(NTD) | 整數 | 上季結算已收金額（元） | `118000` | 是 |

**第一列 Header（直接複製貼至第 1 列）：**
```
律師ID	姓名	案件上限	本季預計結案數	本季累計結案數	上季結算結案數	本季累計計費時數(hr)	季度計費目標(hr)	上季計費時數(hr)	本季收款目標(NTD)	本季已收金額(NTD)	上季已收金額(NTD)
```

**API 讀取：** `客戶主檔!A2:V`

| 欄 | 欄位名稱 | 資料類型 | 說明 | 範例值 | 必填 |

| B | 姓名 | 文字 | 個人姓名或公司全名 | `王○○` | 是 |
| C | 稱謂 | 文字 | `先生` / `小姐`；公司客戶留空 | `先生` | 否 |
| D | 客戶類型 | 文字 | `individual`（個人）/ `company`（公司） | `individual` | 是 |
| E | 統一編號 | 文字 | 公司客戶填寫，個人留空 | `12345678` | 否 |
| F | 身分證字號 | 文字 | 個人客戶填寫，公司留空 | `A123456789` | 否 |
| G | 行動電話 | 文字 | 09 開頭，格式 `09XX-XXX-XXX` | `0912-345-678` | 是 |
| H | 聯絡電話 | 文字 | 市話，可留空 | `02-2381-0000` | 否 |
| I | 電子信箱 | 文字 | Email 地址 | `wang@example.com` | 否 |
| J | 所屬分所 | 文字 | 見下方有效值 | `台北總所` | 是 |
| K | 來源管道 | 文字 | 見下方有效值 | `親友介紹` | 否 |
| L | 初始諮詢項目 | 文字 | 見下方有效值 | `法律諮詢` | 否 |
| M | 客戶狀態 | 文字 | 見下方有效值 | `retained` | 是 |
| N | 負責律師 | 文字 | 律師 ID，對應律師設定 A 欄 | `A` | 否 |
| O | 委任合約狀態 | 文字 | `unsigned` / `signed` / `terminated` | `signed` | 是 |
| P | 利衝查詢狀態 | 文字 | `unchecked` / `clear` / `conflict` | `clear` | 是 |
| Q | 利衝查詢日期 | 日期 | `YYYY-MM-DD`，未查留空 | `2026-03-12` | 否 |
| R | 利衝備註 | 文字 | 衝突說明或查詢附記 | | 否 |
| S | 關聯案件編號 | 文字 | 逗號分隔，對應案件表 A 欄 | `C-2026-041, C-2026-041-A` | 否 |
| T | 初始需求說明 | 文字 | Landing page 表單的「其他備註說明」 | `借貸契約爭議，已提起訴訟...` | 否 |
| U | 內部備註 | 文字 | 所內私有備註，不對客戶公開 | `客戶配合度高，建議定期更新進度` | 否 |
| V | 建檔日期 | 日期 | `YYYY-MM-DD` | `2026-03-10` | 是 |

**有效值清單：**
- **所屬分所：** `台北總所`、`台中分所`、`高雄分所`、`線上諮詢`

### 3. 案件

**用途：** 所有案件主資料，每案一列。子案（上訴、強制執行）也各佔一列，透過 L 欄指向父案。

**API 讀取：** `案件!A2:N`

| 欄 | 欄位名稱 | 資料類型 | 說明 | 範例值 | 必填 |
|----|---------|---------|------|--------|------|
| A | 案件編號 | 文字 | 格式 `C-YYYY-NNN`，子案加後綴如 `-A` | `C-2026-041` | 是 |
| B | 建立日期 | 日期 | `YYYY-MM-DD` | `2026-03-10` | 是 |
| C | 當事人 | 文字 | 當事人姓名或公司名稱 | `王○○` | 是 |
| D | 案由 | 文字 | 案件事由簡述 | `借貸契約爭議` | 是 |
| E | 聲明事項 | 文字 | 訴訟目的或辯護方向 | `請求給付借款` | 是 |
| F | 案件類型 | 文字 | 見下方有效值 | `民事訴訟` | 是 |
| G | 狀態 | 文字 | 見下方有效值 | `active` | 是 |
| H | 負責律師 | 文字 | 律師 ID | `A` | 是 |
| I | 下次期限 | 日期 | `YYYY-MM-DD`，無則留空 | `2026-06-15` | 否 |
| J | 預計結案日 | 日期 | `YYYY-MM-DD`，無則留空 | `2026-10-30` | 否 |
| K | 實際結案日 | 日期 | `YYYY-MM-DD`，結案後填入 | | 否 |
| L | 父案編號 | 文字 | 子案才填，對應本表 A 欄 | `C-2026-041` | 否 |

```

```

## 六、注意事項

1. **欄位順序不得改動**：`sheets.js` 以陣列解構依序讀取（`[A, B, C, ...]`），任何欄位插入都會讓後續欄位對應錯誤。新增欄位只能加在最後一欄。

2. **工作表名稱不得更改**：所有 `fetchRange('工作表名稱!...')` 都以中文名稱定址。

3. **第 1 列為 Header**：資料從第 2 列開始。`fetchRange` 的範圍都從 `A2` 開始，Header 不會被讀取。

4. **日期格式**：一律使用 `YYYY-MM-DD`（西元，非民國），確保 `new Date(dateStr)` 可正確解析。

5. **布林值**：追蹤事項 E 欄請使用 `TRUE` / `FALSE` 全大寫，`sheets.js` 以 `=== 'TRUE'` 判斷。

6. **已知 Bug — 律師設定讀取範圍錯誤**：`sheets.js` 第 66 行 `fetchRange('律師設定!A2:H')` 應改為 `fetchRange('律師設定!A2:L')`，否則 I–L 欄（上季計費、收款相關）永遠讀不到。正式上線前必須修正。

7. **Landing page intake 串接**：`submitIntakeForm()` 目前 POST 格式與 `IntakePage.jsx` 實際送出的欄位尚未對齊（functions 中預期有 `identity`、`preferredDate`、`timeSlot` 等欄位，但表單未收集）。正式串接前需統一。
