# Product Brief — Legal Ops Dashboard

## 產品定位

Demo 階段的純前端法律事務所操作平台。資料來源為 Google Sheets，暫無後端；Demo 驗證後再導入 Supabase。

---

## 使用角色

| 角色 | 主要用途 |
|------|----------|
| 律師 | 查看自己的案件、待辦、期限、相關文件 |
| 管理層 | 整體業績 KPI、財務報表、所有案件概覽 |
| 律師助理 | 資料新增／編輯／維護，全模組存取 |

---

## 核心模組

| 模組 | 功能重點 |
|------|----------|
| 案件追蹤 | 案件列表、狀態、負責律師、截止日期 |
| 文件管理 | 合約／文件上傳、簽署狀態、版本 |
| 帳單／費用 | 計費、發票、付款狀態 |
| 行事曆／期限 | 開庭日期、截止日、提醒 |

## 子案件邏輯（審級聯動）

### 設計原則

新審級需要重新報價與簽約時，以**子案件（Sub-matter）** 處理，而非新建獨立案件。
父案件代表整體客戶委任關係，子案件代表各審級的獨立程序與費用。

### 資料結構

```js
// 父案
{
  id: 'C-2026-001',
  parentCaseId: null,
  subCases: ['C-2026-001-A'],
  status: 'active',
  pendingReview: false,       // 子案結案後觸發為 true
  pendingReviewNote: '',      // 提示文字
}

// 子案
{
  id: 'C-2026-001-A',
  parentCaseId: 'C-2026-001', // 指向父案
  subCases: [],
  status: 'active',           // 有自己獨立的流程狀態
}
```

### 建立案件入口（兩種類型）

```
選擇案件類型
├── 新案件 → 正常建立流程
└── 子案件 → 搜尋並選擇父案
              ↓
         繼承父案資訊（客戶、律師、案件類型）
         填寫本審級特有資訊（審級說明、新報價、新合約）
         子案從「報價」階段開始走流程
```

### 子案結案聯動（出口）

子案拖曳至「結案」時，系統跳出確認提示：

```
「C-2026-001-A（二審）已結案
 父案 C-2026-001 是否同步結案？」

├── 是 → 父案移至結案
├── 否，開立強制執行 → 自動建立新子案，從「報價」開始
└── 暫不處理 → 父案顯示橘色「待確認」旗標
```

**不做自動聯動的原因：** 判決確定後可能仍有強制執行、再審聲請、費用結算等後續，自動結案會造成案件狀態失真。

### Case View 呈現

- 子案卡片：顯示父案號碼標籤（例如 `子案 / C-2026-001`）
- 父案卡片：顯示「子案 N 件進行中」，可點擊跳轉
- 父案有待確認事項時：顯示橘色「待確認」旗標，點擊後出現三選項選單

### 適合新建獨立案件的例外情況

- 衍生出全新當事人組合（反訴、第三人加入）
- 性質完全不同的案件類型（刑事本案結束後另起民事損害賠償）

---

## 技術決策優先順序

1. **法定期間警示的準確性** > 任何 UI 細節
2. **資料不遺失** > 操作便利性
3. **權限邏輯正確** > 功能完整性
